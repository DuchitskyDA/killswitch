# API окна killswitch

Контракт между локальным сервером (`internal/window`) и страницей окна. Сервер запускает команда
`killswitch window`; он слушает только `127.0.0.1` на случайном порту и живёт, пока окно открыто.

## Страница

- Собранная страница лежит в `internal/window/dist` и встраивается в бинарник (`go:embed`). Корень
  каталога — корень сайта: `dist/index.html` отдаётся по `/`, остальные файлы — по своим путям.
- Размер окна задают константы `WindowWidth` × `WindowHeight` в `launch.go` (460 × 700). Окно можно
  растянуть, а без Edge страница открывается обычной вкладкой: вёрстка не должна зависеть от точного
  размера.
- Политика содержимого: `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:;
  font-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`.
  Для страницы это значит: скрипты, стили и шрифты — только своими файлами, без встроенных `<script>`,
  `<style>`, атрибутов `style="…"` и `on…="…"`, без `eval`; картинки — свои файлы или `data:`; запросы —
  только к этому же адресу; никаких внешних адресов.
- Все ответы идут с `Cache-Control: no-store`: файлы страницы браузер не кеширует.

## Сеанс

1. Окно открывается по адресу `http://127.0.0.1:<порт>/open?key=<ключ>`. Ключ одноразовый.
2. Сервер ставит cookie сеанса (`HttpOnly`, `SameSite=Strict`) и отвечает `303` на `/`. Страница о ключе и
   cookie ничего не знает: браузер шлёт cookie сам.
3. Запросы страницы — обычный `fetch` на относительный путь. Дополнительных заголовков не нужно, кроме
   `Content-Type: application/json` у `POST` и `PUT`.

Чего страница делать не должна: читать или хранить ключ, обращаться к серверу с другого адреса,
отправлять формы (`<form>` без скрипта сервер отвергнет по типу содержимого).

## Срок жизни

Сервер завершается, когда окна нет. Правила:

- каждый запрос к `/api/…` продлевает срок на 90 секунд;
- страница шлёт `POST /api/alive` раз в 20 секунд, пока открыта (таймеры свёрнутого окна браузер
  замедляет до раза в минуту — запас на это есть);
- при закрытии страница шлёт `POST /api/alive` с телом `{"closing": true}` — сервер завершится через
  3 секунды, если за это время не придёт другой запрос. Перезагрузка страницы поэтому окно не закрывает:
  новая страница сразу запрашивает состояние.

Сигнал закрытия — из обработчика `pagehide`, запросом, который переживает выгрузку страницы:

```js
addEventListener('pagehide', () => {
  fetch('/api/alive', {
    method: 'POST',
    keepalive: true,
    headers: {'Content-Type': 'application/json'},
    body: '{"closing": true}',
  })
})
```

`navigator.sendBeacon` подходит, только если тело — `Blob` с типом `application/json`.

После завершения сервера запросы не проходят (ошибка сети): странице стоит показать, что окно больше не
работает и его нужно открыть заново.

## Общие правила

- Тело запроса и ответа — JSON в UTF-8. Ответ всегда `Content-Type: application/json`.
- `POST` и `PUT` требуют `Content-Type: application/json`. Тело — один JSON-объект не длиннее 64 КиБ;
  неизвестные поля — ошибка. У `POST /api/check` и `POST /api/alive` тело может быть пустым.
- Действия выполняются по одному: второй запрос ждёт конца первого. `POST /api/alive` не ждёт.
- Списки в ответах никогда не `null` — пустой список это `[]`. Исключение — ключи настроек (см.
  `/api/config`), где `null` значит «ключа нет».
- Тексты (`summary`, `note`, `text`, `message`, `error`) — готовые строки для показа, на русском.

### Ошибки

Ответ с ошибкой — объект с полем `error` (текст для показа):

```json
{"error": "нужен Content-Type: application/json"}
```

| Код | Когда |
|---|---|
| 400 | тело не разобрано: не JSON-объект, неизвестное поле, неизвестный режим |
| 401 | нет сеанса: cookie нет или она чужая; ключ неверный или уже использован |
| 403 | запрос пришёл не с этой страницы: чужой `Host`, `Origin` или `Sec-Fetch-Site` |
| 404 | такого метода API или файла страницы нет |
| 405 | метод HTTP не поддерживается; допустимые — в заголовке `Allow` |
| 409 | защита не настроена: сначала нужно сохранить настройки |
| 413 | тело длиннее 64 КиБ |
| 415 | у `POST`/`PUT` нет `Content-Type: application/json` |
| 422 | настройки или действие отвергнуты проверкой: текст в `error` объясняет, что исправить |
| 500 | сбой на машине: правила не применены, снимок не снят, файл не записан |

У методов `/api/…` ошибки 401 и 403 — тот же JSON с `error`. Строкой текста, а не JSON, отвечают только
`/open` и файлы страницы. Ответ 401 на запрос к API значит, что сеанса больше нет: окно нужно открыть
заново.

## Методы

### GET /api/state

Состояние защиты — то же, что шапка меню.

```json
{
  "os": "windows",
  "configured": true,
  "mode": "on",
  "active": true,
  "tunnels": [{"name": "wg-example", "up": true}],
  "warnings": [{"level": "warn", "text": "незавершённый переход к on (поколение 4): enforce доведёт"}],
  "capabilities": {"repair": true, "endpoints": true, "trust_kinds": ["program"]}
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `os` | строка | `windows`, `linux` или `darwin` |
| `configured` | логическое | файл настроек есть; `false` — показать первую настройку, режимы и проверка ответят 409 |
| `mode` | строка | записанный режим: `on`, `off`, `repair`; пусто — защита не устанавливалась |
| `active` | логическое | наши правила стоят в системе |
| `tunnels` | список | адаптеры, совпавшие с шаблоном туннеля: `name`, `up` (адаптер поднят) |
| `warnings` | список | замечания: `level` — `warn` или `leak`, `text` — строка для показа |
| `capabilities.repair` | логическое | режим `repair` и раздел программ починки есть на этой ОС |
| `capabilities.endpoints` | логическое | адреса серверов туннеля (`tunnel.endpoints`) поддержаны |
| `capabilities.trust_kinds` | список строк | допустимые `kind` доверия: `program`, `user`, `cgroup`, `mark` |

### POST /api/mode

Переключить режим. Тело: `{"mode": "on"}` — `on`, `off` или `repair`.

Ответ 200 — новое состояние в форме `GET /api/state`.

Ошибки: 400 — неизвестный режим; 409 — нет настроек; 422 — режим или настройки не подходят этой машине
(например, `repair` вне Windows); 500 — правила не применены.

### POST /api/check

Проверка утечек — та же, что команда `check`. Тело пустое или `{}`. Проверка идёт до десятков секунд;
сигнал жизни в это время продолжает проходить.

```json
{
  "result": "leak",
  "code": 4,
  "simple": false,
  "summary": "УТЕЧКА",
  "note": "адаптер Ethernet: http 203.0.113.10:80",
  "probes": [
    {"target": "203.0.113.10:80", "family": "v4", "proto": "http", "iface": "Ethernet",
     "class": "leak", "detail": "ответ получен"}
  ],
  "structural": [{"kind": "wfp-tie", "detail": "чужое разрешающее правило"}],
  "tunnels": [{"name": "wg-example", "up": true}],
  "warnings": []
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `result` | строка | `clean` — утечек не найдено, `leak` — утечка, `unsure` — нет уверенности |
| `code` | число | код возврата команды `check`: 0, 4 или 5 |
| `simple` | логическое | простая проверка: целей в настройках нет, проверен один общий адрес |
| `summary` | строка | итог одной строкой |
| `note` | строка | пояснение: при утечке — где она (адаптер и цель либо структурная находка); может быть пустым |
| `probes` | список | пробы: `target` (адрес и порт), `family` (`v4`, `v6`), `proto` (имя пробы: `http`, `udp-echo`, `dns-udp`, `dns-tcp`), `iface` (адаптер), `class` (`blocked`, `leak`, `unsure`, `skipped`), `detail` |
| `structural` | список | находки в правилах без проб: `kind`, `detail` |
| `tunnels` | список | адаптеры туннеля на момент проверки, как в состоянии |
| `warnings` | список | замечания снимка машины, как в состоянии |

Строки `kind` и `detail` — те же, что печатает команда `check`; страница показывает их как есть.

Ошибки: 409 — нет настроек; 422 — настройки не проходят проверку; 500 — снимок машины или статус правил
не получены.

### GET /api/config

Настройки из файла — те же ключи, что в `config.toml` (смысл и допустимые значения — в README, раздел
«config.toml»). Файла нет — все ключи пустые.

```json
{
  "profile": "example",
  "lan": true,
  "trust_mode": null,
  "tunnel": {"interfaces": ["wg-example"], "endpoints": null},
  "trust": [{"kind": "program", "value": "C:\\Program Files\\Example\\client.exe", "destinations": ""}],
  "dns": {"mode": null, "resolvers": null, "health": null},
  "repair": {"programs": null, "names": ["node"]},
  "check": {"targets": null}
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `profile` | строка | имя профиля клиента; пусто — без профиля |
| `lan` | логическое или `null` | доступ к локальной сети |
| `trust_mode` | строка или `null` | `compat` или `strict` |
| `tunnel.interfaces` | список строк или `null` | шаблоны имён адаптеров туннеля |
| `tunnel.endpoints` | список строк или `null` | адреса серверов туннеля |
| `trust` | список или `null` | доверенные клиенты: `kind`, `value`, `destinations` (`any`, `endpoints`; пусто — по `trust_mode`) |
| `dns.mode` | строка или `null` | `open`, `tunnel-up`, `resolvers` |
| `dns.resolvers` | список строк или `null` | адреса DNS-серверов |
| `dns.health` | строка или `null` | проверка живости туннеля |
| `repair.programs` | список строк или `null` | пути программ починки |
| `repair.names` | список строк или `null` | имена программ починки |
| `check.targets` | список строк или `null` | цели проверки утечек |

`null` и пустой список — разное: `null` — ключа в файле нет, действует значение профиля или умолчание;
`[]` — ключ есть и заменяет список профиля пустым. Страница должна сохранять это различие: поле, которое
пользователь не трогал, уходит обратно тем же `null`.

Ошибка: 500 — файл настроек не прочитан или не разобран.

### PUT /api/config

Сохранить настройки. Тело — объект той же формы, что ответ `GET /api/config`, целиком: пропущенный ключ
равен `null`. Настройки проверяются тем же путём, что команда `on`; при включённой защите сразу
применяются.

Ответ 200:

```json
{"saved": true, "message": "сохранено и применено (on)"}
```

Ответ с ошибкой несёт те же поля рядом с `error`:

```json
{"error": "не сохранено: профиль \"нет такого\" не найден", "saved": false}
```

| Поле | Тип | Смысл |
|---|---|---|
| `saved` | логическое | файл настроек записан |
| `message` | строка | что сделано; при ошибке есть, только если файл всё же записан |
| `error` | строка | только при ошибке |

`saved: true` вместе с `error` — файл записан, но правила не применились: настройки новые, защита в
прежнем состоянии, странице стоит показать оба текста.

Ошибки: 400 — тело не разобрано или значение не записать в файл; 422 — настройки отвергнуты проверкой
(файл не тронут); 500 — сбой при записи или применении.

### GET /api/clients

Профили клиентов для этой ОС и отметка, какие клиенты найдены на машине.

```json
{
  "profiles": [
    {
      "name": "example",
      "description": "Пример клиента",
      "detected": true,
      "interfaces": ["wg-example"],
      "trust": [{"kind": "program", "value": "C:\\Program Files\\Example\\client.exe", "destinations": ""}],
      "repair_programs": []
    }
  ]
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `name` | строка | имя профиля — значение для `profile` в настройках |
| `description` | строка | описание для показа |
| `detected` | логическое | клиент найден на этой машине |
| `interfaces` | список строк | шаблоны адаптеров, которые даёт профиль |
| `trust` | список | доверие, которое даёт профиль; форма как в настройках |
| `repair_programs` | список строк | программы починки, которые даёт профиль |

### GET /api/programs

Запущенные программы для выбора по имени (раздел программ починки). Список есть только там, где
`capabilities.repair` — `true`; иначе он пустой.

```json
{"programs": [{"name": "node", "paths": ["C:\\Program Files\\nodejs\\node.exe"]}]}
```

| Поле | Тип | Смысл |
|---|---|---|
| `name` | строка | имя программы — значение для `repair.names` |
| `paths` | список строк | файлы запущенных программ с этим именем |

Ошибка: 500 — список процессов не получен.

### POST /api/alive

Сигнал жизни окна (см. «Срок жизни»). Тело пустое, `{}` или `{"closing": true}`. Ответ 200: `{}`.
